# Internationalization (i18n) Architecture

The project uses two independent i18n systems sharing locale tags (`en-UK`, `de-DE`, `es-ES`, `ar`, `el-GR`, `ie-IE`, `ru-RU`, `tr-TR`; `ar` is right-to-left):
- **Frontend**: JSON dictionaries via `useUiI18n` composable
- **Backend**: Fluent (FTL) files; errors return localized JSON

---

## Frontend: useUiI18n Composable

**File**: `app/composables/useUiI18n.ts`

```ts
const { t, locale } = useUiI18n();

// Template: {{ t('nav.notes') }}
// Script: const title = t('page.title');
```

**Behavior**:
- Reads/saves locale from `"lang"` cookie
- Returns translated string or defaults to en-UK, then the key itself

### Locale Files

**Location**: `app/locales/{locale}.json`

```json
{
  "nav.home": "Home",
  "auth.login": "Login",
  "page.notes.heading": "Notes",
  "dialog.deleteTitle": "Confirm Deletion"
}
```

**Naming**: Use dot notation, group by feature (`nav.`, `auth.`, `page.`, `button.`, `dialog.`, `message.`)

### Adding Frontend Translations

1. Add the key to every locale file in `app/locales/`
2. Use in component: `{{ t('your.key') }}`
3. Test with Header language switcher

---

## Backend: Fluent Files

**Files**: `notes/src/langs/{locale}/main.ftl`, compiled in with `include_str!` in `notes/src/i18n.rs` (a new locale needs an entry there too)

```
unauthorized = Unauthorized
note-not-found = Note not found
internal-error = Internal server error
```

### Error Response Format

Handlers now return localized JSON errors:

```rs
#[derive(Serialize)]
struct ErrorResponse {
	message: String,
}

fn error_response(state: &AppState, locale: &str, status: StatusCode, key: &str) -> ApiError {
	let msg = state.i18n.t(locale, key);
	(status, Json(ErrorResponse { message: msg }))
}
```

**Locale resolution** (Ask by Accept-Language header; fallback: language-only match → default en-uk → key itself):

```rs
let locale = requested_locale(&headers, state.i18n.default_locale());
Err(error_response(&state, &locale, StatusCode::NOT_FOUND, "note-not-found"))
```

## Frontend Consumption

Frontend stores already extract `message` from error JSON:

```ts
async function throwForResponse(response: Response): Promise<void> {
	if (response.ok) return;
	const data = (await response.json()) as { message?: string };
	throw new Error(data?.message || `HTTP ${response.status}`);
}
```

Send locale to backend:

```ts
const language = useCookie("lang").value || "en-UK";
fetch("/api/notes", { headers: { "Accept-Language": language } });
```

## Best Practices

- **Frontend**: Never hardcode user-visible text; group by feature (nav.*, auth.*, etc.)
- **Backend**: Only translate user-facing errors; keep logs in English
- **Shared**: Use consistent terminology across languages; test at least one non-English locale and `ar` (RTL)
